# Gate: Reviews Ready

Это готовность ревью-пакета, не готовность продукта. Для ручного запуска рассматривать явно назначенный scope; пропущенную обязательную роль автоматического запуска нельзя отмечать N/A.

PASS: все назначенные отчёты complete, обязательные условия выполнены. LIMITED: назначенная область оценена с конкретными неблокирующими ограничениями. FAIL: missing/blocked профиль обязательного запуска, существенная несовместимость источников/версий, непроверяемые основные выводы либо нарушение независимости.

- [ ] ⛔ Для автоматического запуска все пять workers terminal и все пять отчётов получены; несовпадение/падение явно показано.
- [ ] ⛔ Run/revision/capture совпадают; смешение старого и нового evidence исключено.
- [ ] ⛔ UX walkthrough и Nielsen выполнены в заявленной области либо непроведённое ограничивает итог; каждый отчёт содержит What works well и findings/явное отсутствие замечаний.
- [ ] ⛔ Каждый подтверждённый finding имеет layer/source/evidence/verify; недоказанное отдельно, с причиной.
- [ ] ⛔ Дубли объединены без потери origins; противоречия рассмотрены, продуктовые развилки не решены молча.
- [ ] Must fix / Should fix / Can stay / To verify различены; принятие риска не выдумано.
- [ ] ⛔ Каждое требующее действия замечание, вопрос или проверка имеет маршрутизацию по причине: reason_type, основание/пробел, ответственный, обязательность, действие и критерий проверки. UNKNOWN не выдан за доказанный дефект; отсутствие файла не выдано за отсутствие решения.
- [ ] Severity, layer, origins и разделение Must fix / Should fix / Can stay / To verify сохранены; новая классификация их не заменяет. Необязательность и принятие риска имеют основания.
- [ ] ⛔ В сводке выбран один ближайший шаг с причиной, одним основным ответственным, нужными ID и критерием проверки; участники не подменяют владельца списком ролей, required items не скрыты под none. При отсутствии действий границы вывода названы без автоматического ACCEPT продукта.
- [ ] Зависимости шага подтверждены; продуктовый вопрос не останавливает независимые задачи. Полная маршрутизация сохраняет остальных владельцев, непроверенное направлено на проверку, а не на исправление.
- [ ] Маршрутизация, критерии проверки и нужные reviewers указаны без технического плана ремонта и автоматического запуска исправлений.
- [ ] Preserve имеет evidence и защищает хорошие части.
- [ ] Один synthesis-data согласован с Markdown, включая routing и next_step: IDs разрешаются, причины, владельцы и обязательность совпадают. Гейт, полнота и ближайшее действие понятны без чата.

- [ ] Supplemental Playwright evidence имеет реальные paths/hashes и совпавшие условия; live probes, static observations и failures инструмента различены.
- [ ] UX N1–N10 coverage содержит scopes/status/evidence/reasons, а не только список эвристик.

- [ ] Синтезатор создал только synthesis.md; новые проверки назначены соответствующему reviewer либо остались To verify. Supplemental уточнения получены от роли и прошли повторный barrier.

Для отдельных пунктов используй PASS / FAIL / NOT_CHECKED / N/A; итог Reviews Ready — PASS / LIMITED / FAIL.
