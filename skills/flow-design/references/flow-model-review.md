# Проверка модели flow

| Проверка | Что искать |
| --- | --- |
| Цель и граница | Путь заканчивается наблюдаемым продуктовым результатом; точка входа существует в текущем контексте. |
| Покрытие | Каждый P0 отражён flow, веткой, guard или состоянием. Исключённые сценарии остаются видимыми с основаниями. |
| Контракт | Пользовательские шаги не обещают неподтверждённые права, лимиты и эффекты. Обязательные UI/DS/платформенные ограничения сохранены. |
| Исполнители | Действия человека отделены от работы системы и внешних зависимостей. Смена роли/контекста и передача результата явны. |
| Выбор | Условия ветвей понятны, релевантные исходы покрыты; пересечения разрешены правилом приоритета, если допустимы. |
| Граф | Нет недостижимых необходимых узлов, случайных dead ends или бесконечных циклов; все значимые ветви имеют завершение или recovery. |
| Состояния | Guard и переход согласованы с правилами; визуальная «успешность» не заменяет подтверждённый системный эффект. |
| Данные | Известно, что сохраняется при возврате/refresh, что теряется и что уже применено. Неизвестный контракт помечен явно. |
| Async / повтор | Если применимы, видны ожидание, resume, частичный результат, неопределённый исход, допустимый повтор и отмена. |
| Безопасное завершение | Нет действий после потери права; отмена не обещает неподтверждённый rollback; повтор не скрывает риск повторного эффекта. |
| Читаемость | Одинаковые ветви не дублируются без нужды; диаграммы имеют легенду и manageable размер. |
| Паритет представлений | ID, узлы, ветви и результаты совпадают в таблицах и Mermaid, а также в отдельном представлении, если оно входит в выбранный формат; статус синхронизации подтверждён. Не выбранные локальное представление/FigJam — N/A, без снижения готовности модели. |

Результаты проверок переноси в один `flow.md`. Не изменяй установленную бизнес-логику, чтобы исправить диаграмму: предложи решение или обозначь blocker.
