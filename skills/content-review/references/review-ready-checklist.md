# Gate: Review Ready

Проверить качество отчёта отдельно от качества продукта. Отчёт с серьёзным дефектом может быть качественным; неосмотренная область не становится проверенной при отсутствии findings.

PASS: все обязательные пункты выполнены и применимая область проверена. LIMITED: evidence достаточно для названных выводов, но некоторые проверки недоступны и явно ограничены. FAIL: недостоверные claims, несовместимая revision, нарушена независимость либо нет основания для основных выводов. Даже при FAIL вернуть отчёт с ограничениями.

- [ ] ⛔ Предмет, версия, пользовательская задача и источники названы; для автоматического запуска совпали run_id/revision/capture_sha256.
- [ ] ⛔ Соблюдён read-set, авторские оправдания и чужие findings не использованы; продукт/evidence не изменены.
- [ ] ⛔ Findings имеют severity/layer/location/source/evidence/verify/status и наблюдаемое последствие; новые статусы open.
- [ ] ⛔ Есть What works well с основанием либо честная невозможность оценки; findings или явное «замечаний нет в проверенной области».
- [ ] ⛔ Непроведённое/неизвестное не выдано за PASS; эвристика не выдана за пользовательское исследование.
- [ ] ⛔ Один review-data-блок соответствует тексту; устойчивые IDs и пути существуют.
- [ ] термины/язык и источник установлены.
- [ ] labels errors feedback проверены в состояниях.
- [ ] длинные значения/форматы рассмотрены по доступному scope.

## Самостоятельная browser проверка

- [ ] ⛔ При доступном тестовом прототипе выполнены значимые probes своей роли через Playwright; static screenshots не выданы за interaction/focus/recovery checks.
- [ ] ⛔ URL/revision/fixture и независимый context установлены; shared backend test data изолированы или ограничения явно записаны.
- [ ] ⛔ Выводы о дефектах отделены от locator/automation failures и непроверенных гипотез; target evidence просмотрено.
- [ ] Созданные supplemental screenshots/traces/logs имеют реальные пути/хэши и ссылки из checks/findings; source capture не менялся.
- [ ] Для недоступного браузера/состояния стоят NOT_CHECKED/limitations и partial, без выдуманного live PASS.

## Профильное покрытие
- [ ] dynamic copy проверена после реальных действий.
- [ ] ошибки partial counts recovery соотнесены с данными/контрактом.
- [ ] форматы и длинный текст проверены в заявленных локалях/viewport или ограничены.

Для каждой строки отчёта укажи PASS / FAIL / NOT_CHECKED / N/A, а общий Review Ready — PASS / LIMITED / FAIL. Status complete/partial/blocked и decision_status N/A укажи отдельно.

## Доставка результата (отдельно от профильного гейта)

- [ ] Папка задачи выбрана по `artifact-contract.md`; основной документ и приложения действительно сохранены, либо невозможность записи явно сообщена.
- [ ] Пользователю переданы краткий вывод, ссылки и полный Markdown той же версии прямо в чате; сводка/ZIP не заменяют текст. Для субагента основной сессии переданы отчёт и обязанность доставки; пользовательская доставка завершена только после её ответа.
- [ ] Ограничения сохранения, доступа и неполного дублирования названы явно; они не выданы за дефекты продукта. В связке evidence/review основная сессия доставила все реально полученные отчёты и назвала отсутствующие.
