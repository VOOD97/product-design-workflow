# Контент: задача, состояния и реальная реакция

## Матрица проверки

| Область | Вопросы | Playwright probe | Основание |
|---|---|---|---|
| Термины | Один объект имеет одинаковое имя? Не смешаны пользовательские/внутренние сущности? | Пройти list/detail/action/result, сравнить реальные labels | Glossary, contract или явно internal consistency |
| CTA | Ясно действие, объект и последствия? Label соответствует actual result? | Нажать safe test CTA, сравнить confirmation и outcome | Заданный сценарий и observed sequence |
| Инструкции | Условия ввода/формат/ограничение показаны в нужный момент? | Focus/fill invalid и valid values, посмотреть hints | Реальный validation contract; не придуманное правило |
| Ошибки | Названы место/причина/доступный recovery? Не обещана невозможная операция? | Вызвать предусмотренную validation/error fixture и исправить | Error → action → actual outcome; retained data |
| Partial feedback | Counts, labels и next steps соответствуют частичному результату? | Submit → partial → раскрыть failed → retry по scope | Fixture counts и контракт повторного действия |
| Числа/даты | Понятны единицы, precision, locale, timezone и plural forms? | Данные 0/1/несколько/длинное допустимое значение, заданный locale | Product glossary/localization requirement |
| Длинный текст | Важный смысл не потерян в truncate/wrap? Есть пригодное раскрытие? | Narrow viewport, scroll, expand/tooltip keyboard alternative | Readability/actual access, не только наличие строки в DOM |
| Подтверждение/опасность | Последствия и объекты названы до эффекта? Label не маскирует необратимость? | Пройти confirmation на синтетических данных | Binding rule о действии; не абстрактная «страшная кнопка» |

## Порядок

Сначала пользовательская задача и смысл, затем consistency, затем формат/редактура. Не редактировать copy и не генерировать новый tone of voice вместо оценки.

Проверяй dynamic text **после реальных действий**, а не только default screen. Сравни видимые counts с test fixture; metadata или текст spec не доказывают, что нужное сообщение появляется. Для API/error response simulation маркируй искусственное условие и не заявляй реальную причину сбоя.

Контент может быть визуально обрезан, хотя DOM содержит полный текст: открой screenshot и проверь реальный доступ. При tooltip проверь применимость keyboard/touch; не требуй tooltip как универсальное решение.

Числовые/календарные пороги берутся из контракта. Не придумывать правило оформления из личного вкуса. Если заявлена одна локаль, остальные N/A или вне scope; не выдавать проверку одной строки за полноценную локализацию.

## Findings и границы

Наблюдение: конкретная строка в конкретном state и actual action/result. Последствие: неправильное ожидание, потеря понимания результата, ошибка выбора/восстановления. Source: glossary/contract либо применимый принцип с ограниченной уверенностью.

«Текст мне не нравится», стиль без tone-of-voice источника и другой допустимый синоним не становятся High. Явная неверная сумма/единица/объект опасного действия может быть существенной проблемой без орфографических ошибок.

Текстовое нарушение обычно layer ui; если сообщение противоречит продуктовому правилу, указать product/implementation с конкретным основанием, не превращая Content Reviewer в инженера code review. Зафиксировать criterion исправности и reproduce steps, а не молча внедрять свою формулировку.
