# Gate: Competitive Research Ready

Проверить самостоятельное исследование и выбранный формат результата: document или document+stand. Визуальное представление проверяется только для document+stand. Ни готовый requirements.md, ни запуск других процессов не обязательны.

## Как пользоваться

В раздел 12 отчёта перенеси статус каждого пункта и раздел/ID доказательства либо причину ограничения. ⛔ — обязательное условие. N/A требует причины и не заменяет неизвестное. Открытый вопрос, меняющий область или существенный вывод, является блокером; его документирование не означает закрытия.

- PASS: все применимые пункты выполнены, блокеров нет; при document+stand стенд собран и проверен доступными визуальными средствами. При document отсутствие стенда, stand-data и средств его сборки/просмотра не снижает PASS.
- LIMITED: обязательная аналитическая часть выполнена; остались только ограничения, не меняющие ключевые выводы. При document+stand допустимо отсутствие средств сборки/браузера, если Markdown и данные готовы, причина и способ продолжения названы. Стенд в этом случае честно отмечен как не собран или визуально не проверен.
- FAIL: область не определена, отсутствует evidence для ключевых выводов, открыты значимые блокеры, нарушена достоверность или при document+stand в доступной среде сборка/проверки выявили неисправность требуемого стенда.

Успешный exit code сборщика сам по себе не означает PASS исследования. Выпуск отчёта не требует согласования всех наблюдений человеком; продуктовые решения в нём не принимаются.

## Область и поиск

- [ ] ⛔ Проблема, пользователь, scope и RQ понятны; опора на текущий запрос TASK допустима без файла требований.
- [ ] Доступный релевантный артефакт прочитан, его версия/актуальность и используемая область названы; при отсутствии N/A без требования запуска другого процесса.
- [ ] ⛔ У каждого RQ есть связь с задачей, критерий достаточности, статус answered / partial / open и причина ограничений.
- [ ] ⛔ С начала исследования рассмотрены прямые конкуренты, аналогичные продукты, смежные рынки и неожиданные паттерны. По умолчанию выполнен поиск за пределами прямых конкурентов: есть запросы, источники и результаты, включая отсутствие релевантных находок. Если поиск ограничен конкурентами, указаны явно узкий запрос пользователя или конкретное ограничение, его основание и влияние на выводы.
- [ ] Для исключённых направлений указаны причины; у включённых аналогов объяснены структурное сходство и пределы переноса. Неожиданные паттерны искали целенаправленно, если направление не исключено обоснованно.
- [ ] Категории не заполнялись ради количества: отсутствие находок после добросовестного поиска само по себе не снижает гейт. Существенные незакрытые RQ и ограничения оцениваются по общим правилам.
- [ ] Запросы/каналы, даты, бюджет и причина остановки записаны; ширина поиска соразмерна задаче.

## Evidence

- [ ] ⛔ У существенного REF есть система, конкретный источник/место, дата и условия, observation, interpretation и relevance.
- [ ] ⛔ Собственное наблюдение, описание документа и отзыв атрибутированы раздельно; маркетинговое заявление не выдано за лично проверенный flow.
- [ ] ⛔ Нет выдуманных систем, URL, цитат, наблюдений и скриншотов; учебные SVG не использованы как evidence.
- [ ] Уверенность и её основание указаны отдельно от релевантности. Документация подтверждает лишь описанное ею поведение, не визуальную проверку.
- [ ] Файлы evidence существуют, подписи объясняют наблюдение; для поведения указана последовательность/таймкод, где необходимо.
- [ ] Отсутствующий файл имеет причину и доступное текстовое/ссылочное основание. Скриншот не является обязательным для каждого факта.

## Анализ

- [ ] ⛔ Паттерны описывают принцип и условия применения, trade-offs и ограничения, связаны с REF. Если обобщение невозможно, это объяснено; выдумывать PAT для полноты нельзя.
- [ ] Распространённость ограничена выборкой n/N независимых систем. Standard / rare / emerging имеют отдельные основания; один пример допускается как observed.
- [ ] Контрпримеры рассмотрены. Преимущества, эффективность и пользовательские ожидания не объявлены доказанными без соответствующих данных.
- [ ] Сравнение использует общие критерии. Необязательная матрица сохраняет unknown; no имеет прямое основание в исследованной конфигурации.
- [ ] ⛔ Выводы связаны с задачей и evidence. GAP/OPP либо обоснованы, либо честно не выявлены; OPP — HYPOTHESIS.
- [ ] Найденные паттерны не превратились в Must и не отменили binding-ограничения. Предложения по изменению вводных отделены от принятых решений.
- [ ] По исходным требованиям выполнено сопоставление, если они доступны; иначе N/A. Выбор готового решения и редактирование исходного артефакта не выполнены без поручения.

## Доставка и стенд

Формат и основание выбора должны быть записаны в отчёте. Для document проверки stand-data, сборки, работы и пересборки стенда — N/A: Research Stand not-required. Для document+stand эти проверки применимы; недоступность инструмента — NOT_CHECKED с ограничением, а не N/A. Не меняй согласованный формат ради PASS.

- [ ] ⛔ Markdown содержит полное исследование, ограничения и результаты проверки; самодостаточен без чата.
- [ ] ⛔ Ровно один блок stand-data; его видимые тексты, статусы и значения вручную сверены с аналитическими разделами.
- [ ] Сборщик извлёк канонические данные из Markdown, проверил структуру/ID/файлы; предупреждения оценены. JSON и HTML не редактировались независимо.
- [ ] Стенд открывается, вкладки, переходы, фильтры, сравнение, evidence и клавиатура работают; или отсутствие визуальной проверки отмечено с причиной.
- [ ] Гейт, статус и ограничения обновлены перед окончательной пересборкой; копия полного Markdown доступна из стенда.
- [ ] Для передачи включены Markdown и все нужные evidence, а при document+stand также HTML и остальные файлы стенда; одиночный HTML не назван полностью самодостаточным при внешних файлах.
- [ ] Нет персональных данных и материалов, не предназначенных для выдачи. Публикация материалов в публичном репозитории рассматривается отдельно от их использования в анализе.

## Доставка результата (отдельно от профильного гейта)

- [ ] Папка задачи выбрана по `artifact-contract.md`; основной документ и приложения действительно сохранены, либо невозможность записи явно сообщена.
- [ ] Пользователю переданы краткий вывод, ссылки и полный Markdown той же версии прямо в чате; сводка/ZIP не заменяют текст. Для субагента основной сессии переданы отчёт и обязанность доставки; пользовательская доставка завершена только после её ответа.
- [ ] Ограничения сохранения, доступа и неполного дублирования названы явно; они не выданы за дефекты продукта. В связке evidence/review основная сессия доставила все реально полученные отчёты и назвала отсутствующие.
