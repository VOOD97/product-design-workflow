# Interface Ready — проверяемый чеклист

Для каждой строки внеси в `ui-spec.md`: `PASS / FAIL / NOT_CHECKED / N/A`, ссылку на доказательство, причину N/A и блокирующий вопрос при наличии. Чекбокс — отметка выполненной проверки, не замена её результата. Отсутствие evidence не является PASS.

- [ ] Задача, роль, scope, P0 и источники определены; предположения отделены от фактов.
- [ ] Существующие принятые продуктовые/визуальные ограничения сохранены; material proposals имеют статус и подтверждение или остаются draft. Для открытого существенного выбора показаны опора, рекомендация и компромисс либо объяснён недостаток оснований; вопрос касается действительно неизвестного.
- [ ] Реакция пользователя или явное делегирование отражены в решениях без повторного согласования известного. Обсуждение одного выбора не сократило запрошенное покрытие и не остановило независимые части работы.
- [ ] Все P0-сценарии и flow steps покрыты screen × state с устойчивыми UI-ID.
- [ ] Каждый экран имеет purpose, content/layout, компоненты, действия, условия переходов и доступный результат.
- [ ] Значимые loading/empty/error/success/partial/permission states предусмотрены; N/A объяснён.
- [ ] Error/retry/cancel и сохранение данных определены в пределах scope.
- [ ] Существующие DS/tokens/components переиспользованы и сверены с конкретным источником.
- [ ] Если DS отсутствует: provisional scope явно указан; он не объявлен принятым каноном продукта; существенные gaps имеют владельца/вопрос.
- [ ] Responsive behavior определён и реально просмотрен на зафиксированных viewport; поддержка платформ не додумана.
- [ ] Labels, semantics, focus visibility/order, dialog lifecycle, dynamic feedback и non-color communication рассмотрены и проверены в доступном объёме.
- [ ] Design Stand отрисовывает все P0 screens × states, а не только текст/плейсхолдеры.
- [ ] Выбор состояния, viewport и deep links воспроизводимы; UI/S/FLOW-ID видны.
- [ ] Стенд и спецификация относятся к одной ревизии; material changes отражены в обоих.
- [ ] Стенд использует реальные проектные компоненты/токены, либо явно описанный provisional слой.
- [ ] Стенд запущен, просмотрен и сопоставлен с конкретными визуальными опорами; path/команда действительны.
- [ ] Контент, длинные значения, overflow и существенные states проверены глазами.
- [ ] Все ограничения, конфликты и неизвестные сохранены; непроверенное не выдано за соответствие или дефект.
- [ ] Результат передан одним `ui-spec.md` плюс связанные stand assets; production implementation не изменена молча.

## Итог

- **PASS** — обязательные применимые условия подтверждены, существенный контракт принят или выбор делегирован; P0 покрытие и обязательные проверки завершены.
- **LIMITED** — обязательные условия выполнены, остаётся явно неблокирующее ограничение охвата/доставки. Не скрывай обязательную проверку под этим статусом.
- **FAIL** — нарушено обязательство, отсутствует P0 покрытие, обязательное решение остаётся proposed/unknown либо существенная обязательная проверка NOT_CHECKED. Назови причину; непроверенное не выдавай за доказанный дефект.

Статус полноты complete/partial/blocked и decision_status запиши отдельно по artifact-contract.md. При отсутствии браузера обязательная проверка получает NOT_CHECKED; черновик всё равно передай с конкретным условием завершения.

## Доставка результата (отдельно от профильного гейта)

- [ ] Папка задачи выбрана по `artifact-contract.md`; основной документ и приложения действительно сохранены, либо невозможность записи явно сообщена.
