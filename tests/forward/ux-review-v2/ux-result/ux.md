# UX-ревью формы приглашения сотрудников

## Область и источники

Роль — администратор; цель — отправить приглашения и понять результат. Источник обязательного контракта — [task.md](../ux-input/task.md): до отправки видны адреса и роли; partial показывает числа успешных/неуспешных и список ошибок; Retry только для неуспешных. Отправка приглашения не означает регистрацию сотрудника.

Read-set: task.md и [observations.md](../ux-input/observations.md), пункты 1–7; прочитаны только назначенный ux-review/SKILL.md и его review-protocol, playwright-review, cognitive-walkthrough, nielsen-evaluation, review-ready-checklist и review-template. Другие skill folders, продукт и предыдущие ревью не читались. Хэши входов — в review-data. run_id/revision/capture_sha256 неизвестны и равны null; хэши текстов не подменяют capture.

Это экспертная оценка предоставленного учебного текста. Самостоятельных действий в продукте и Playwright checks выполнено **0**: URL и interactive доступ прямо отсутствуют по заданию. Связь текста с реальной версией продукта неизвестна. Статус **partial**, gate **LIMITED**.

Подготовка администратора неизвестна. Entry — форма перед отправкой; успех — понятный итог приглашений, включая неуспешную часть и допустимый recovery. Новичок используется лишь как условная экспертная линза. All-success, invalid input, pending, exit и recovery completion не описаны.

## What works well

- В тексте перед отправкой представлены email и role каждого участника: администратор получает контекст для проверки выбора (P01, наблюдение 1).
- Числа 3/2 явно разделяют успешную и неуспешную часть (P02, наблюдение 2).
- «Приглашения отправлены» обозначает отправку и не обещает подтверждённую регистрацию (P05, наблюдение 6). Фактическая доставка не проверена.

## Findings

### UX-001 — Частичный результат: две строки ошибок E4021

**Medium · ui · N9 · open · confidence: medium**

Наблюдение: По учебному наблюдению 3 обе ошибки содержат E4021 без пояснения причины и без действия исправления.

Влияние: Администратору может быть трудно понять, что исправить перед повтором; эффект оценён экспертно, пользователями не измерялся.

Источник: Задача администратора — отправить приглашения и понять результат; при частичном успехе нужен список ошибок. N9: понятная исправляемая причина и допустимое восстановление; код оценивается вместе с окружающим объяснением. Evidence: observations.md, наблюдение 3; точные пути в review-data.

Verify: После появления URL воспроизвести 3 успешных и 2 неуспешных приглашения в отдельном безопасном fixture; открыть ошибки, проверить объяснение и доступное действие, пройти исправление/retry и повторить с чистым fixture. Проверить альтернативу: есть ли доступная расшифровка вне строки ошибки.

Limits: Основание — учебный текст, не наблюдение интерфейса reviewer. Реальная причина E4021 и возможность исправления не установлены; конкретное исправление не предписывается.

### UX-002 — Частичный результат: кнопка «Повторить всё»

**Medium · ui · N4 · open · confidence: medium**

Наблюдение: В наблюдении 4 recovery control назван «Повторить всё», хотя контракт ограничивает Retry неуспешными приглашениями.

Влияние: Подпись может создать ожидание повторения всех пяти адресов и затруднить выбор безопасного recovery. Фактический повтор успешных записей или дублирование приглашений не доказаны.

Источник: При частичном успехе Retry только для неуспешных. N4: смысл controls/states последователен; дополнительно N2 и N9. Evidence: observations.md, наблюдение 4; точные пути в review-data.

Verify: На fixture с IDs a,b,c=success и d,e=failed после обычного клика Retry проверить видимый охват и submitted IDs d,e, сохранность a,b,c; повторить с чистым fixture. Если submitted IDs только d,e, backend-гипотеза опровергнута, а вопрос подписи оценивается по контексту.

Limits: Подтверждена только формулировка в предоставленном тексте. UI-контекст слова «всё», actual submitted IDs и backend-повтор неизвестны; severity не основана на гипотетических дублях.

## Ограничения и открытые вопросы

- Только учебные текстовые наблюдения, не browser trace, screenshot или реальное пользовательское исследование.
- URL, revision, capture, Playwright/session, fixture и viewport отсутствуют; browser_checks B01–B08 NOT_CHECKED.
- Неизвестны actual submitted IDs, backend retry, permissions, persistence, доставка и регистрация.
- Keyboard, Back/Cancel, узкий viewport, скорость и processing, invalid input и реальные recovery не проверены.
- Начальная подготовка/частота работы администратора UNKNOWN; lens новичка — экспертная условность.

Для продолжения нужны URL и идентификация тестовой версии, безопасные независимые fixtures/reset, ожидаемая семантика E4021 и permitted retry evidence. Открытые вопросы: что означает «всё» в окружающем контексте; какие IDs реально отправляет Retry; как объясняются причины failed; что показывает help; какое сохранение ввода ожидается при выходе. Отсутствие этих данных само по себе не объявлено дефектом продукта. Продукт, skill и исходные наблюдения не изменялись; новое browser evidence не создавалось.
